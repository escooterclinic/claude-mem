## 3. How runtime is selected

`CLAUDE_MEM_RUNTIME=server` (or legacy `server-beta`, trimmed and case-folded) selects server. All other values default to worker. The value comes from settings loaded once; environment overrides file settings. The usual file is `~/.claude-mem/settings.json`, but `CLAUDE_MEM_DATA_DIR` can relocate it. Resolving actual server runtime additionally requires nonempty server URL, API key, and project ID; canonical `CLAUDE_MEM_SERVER_*` keys take precedence over legacy `CLAUDE_MEM_SERVER_BETA_*`. Missing any required value makes `resolveRuntimeContext()` return worker. **This function is used by session-init, not by contextHandler.**

**`src/services/hooks/runtime-selector.ts:39-110`**

```typescript
export function selectRuntime(): SelectedRuntime {
  const settings = loadFromFileOnce();
  const raw = (settings.CLAUDE_MEM_RUNTIME ?? 'worker').trim().toLowerCase();
  // Accept both the canonical `'server'` (Phase 1a) and the legacy
  // `'server-beta'` literal for back-compat with installed settings.json.
  if (raw === 'server' || raw === 'server-beta') return 'server';
  return 'worker';
}

export function buildServerContext(): ServerRuntimeContext | null {
  const settings = loadFromFileOnce();
  // Phase 1a: read new keys first, fall back to legacy `*_BETA_*` keys so
  // existing settings.json files keep resolving the server runtime.
  // Treat empty string the same as missing — `settings.json` populated from
  // `SettingsDefaults` will write `""` for unset keys, and we want those to
  // fall through to the legacy keys (not short-circuit to empty).
  const pickFirstNonEmpty = (...candidates: Array<string | undefined>): string => {
    for (const c of candidates) {
      const trimmed = (c ?? '').trim();
      if (trimmed.length > 0) return trimmed;
    }
    return '';
  };
  const serverBaseUrl = pickFirstNonEmpty(
    settings.CLAUDE_MEM_SERVER_URL,
    settings.CLAUDE_MEM_SERVER_BETA_URL,
  );
  const apiKey = pickFirstNonEmpty(
    settings.CLAUDE_MEM_SERVER_API_KEY,
    settings.CLAUDE_MEM_SERVER_BETA_API_KEY,
  );
  const projectId = pickFirstNonEmpty(
    settings.CLAUDE_MEM_SERVER_PROJECT_ID,
    settings.CLAUDE_MEM_SERVER_BETA_PROJECT_ID,
  );

  if (!serverBaseUrl) {
    logger.warn('HOOK', '[server-fallback] reason=missing_base_url');
    return null;
  }
  if (!apiKey) {
    logger.warn('HOOK', '[server-fallback] reason=missing_api_key');
    return null;
  }
  if (!projectId) {
    logger.warn('HOOK', '[server-fallback] reason=missing_project_id');
    return null;
  }

  const config: ServerClientConfig = {
    serverBaseUrl,
    apiKey,
  };
  return {
    runtime: 'server',
    client: new ServerClient(config),
    projectId,
    serverBaseUrl,
  };
}

export function resolveRuntimeContext(): RuntimeContext {
  if (selectRuntime() !== 'server') {
    return { runtime: 'worker' };
  }
  const ctx = buildServerContext();
  if (!ctx) {
    return { runtime: 'worker' };
  }
  return ctx;
}
```

## 4. Server context contract and return value

`contextObservations(input)` returns a **Promise of a JSON object**, not a string. The text is `result.context`; `result.observations` contains the matched rows. The request is authenticated JSON `POST /v1/context` with required nonempty `projectId` and nonempty `query`, optional integer `limit` (1–50; Postgres default 10), and optional nullable `platformSource`. The payload builder normalizes platformSource when supplied. This is query-based FTS context, not the worker's recent-session timeline protocol; a blank query will not satisfy its schema.

The generic client parses JSON and casts it to the declared type; it does not runtime-validate the response fields. On an empty successful response it returns `{}` cast as the response type, so the interface alone does not guarantee `.context` is present.

## 5. Exact Claude Code SessionStart call graph

```text
plugin/hooks/hooks.json SessionStart (startup|resume|clear|compact)
  -> bun-runner.js worker-service.cjs start
  -> bun-runner.js worker-service.cjs hook claude-code context
  -> src/services/worker-service.ts case 'hook'
  -> hookCommand('claude-code', 'context')
  -> getEventHandler('context') -> contextHandler
  -> adapter.normalizeInput(stdin), input.platform = 'claude-code'
  -> contextHandler.execute(input)
  -> executeWithWorkerFallback(GET /api/context/inject?projects=...&platformSource=claude)
  -> ensureWorkerAliveOnce -> workerHttpRequest -> buildWorkerUrl -> fetch
  -> SearchRoutes.handleContextInject
     -> optional local welcome-hint early return
     -> optional syncClient.pullOnce({ timeoutMs: 1500 })
     -> generateContextWithStats (context-generator re-export)
     -> ContextBuilder.initializeDatabase -> new Database(DB_PATH, {readonly:true, create:false})
     -> queryObservationsMulti + querySummariesMulti (local SQLite)
     -> fitContextForDelivery -> buildContextOutput -> text
  -> res.send(contextResult.text), Content-Type text/plain
  -> contextHandler trims text -> hookSpecificOutput.additionalContext
  -> optional second GET with colors=true -> systemMessage (terminal display)
  -> claudeCodeAdapter.formatOutput -> emitModelContext -> stdout JSON
```

The worker URL uses configured worker host/port; the database is local to that worker process. In the usual local-worker setup this is the machine's local SQLite corpus. It is not the configured Postgres server URL. A configured sync pull can populate SQLite, but does not change the renderer into a `/v1/context` consumer.

The separately registered **UserPromptSubmit** hook runs `hook claude-code session-init`, which can start the server session. Thus the lifecycle uses both handlers at different events; the actual SessionStart context chain uses `contextHandler` plus the worker HTTP route, **not sessionInitHandler**. The route is `/api/context/inject`; `/context/${primaryProject}` below is a synthetic cwd passed into the generator, not the HTTP route.

```typescript
  const config = loadContextConfig();
  const cwd = input?.cwd ?? process.cwd();

  const project = projects[projects.length - 1] ?? context.primary;

  if (!rawDb) {

  try {
    const db = { db: rawDb };
    const platformSource = input?.platformSource
      ? normalizePlatformSource(input.platformSource)
      : undefined;

      Boolean(input?.full)
```

```typescript
export function countObservationsByProjects(db: DatabaseOwner, projects: string[], platformSource?: string): number {
  if (projects.length === 0) return 0;
  const projectPlaceholders = projects.map(() => '?').join(',');
  const row = db.db.prepare(`
    SELECT COUNT(*) as count
    FROM observations o
    LEFT JOIN sdk_sessions s ON o.memory_session_id = s.memory_session_id
    WHERE (o.project IN (${projectPlaceholders})
       OR o.merged_into_project IN (${projectPlaceholders}))
      AND (? IS NULL OR s.platform_source = ?)
  `).get(...projects, ...projects, platformSource ?? null, platformSource ?? null) as { count: number } | undefined;
  return row?.count ?? 0;
}
```
